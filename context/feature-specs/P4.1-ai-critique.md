# P4.1 — AI Design Critique

## Goal

AI-powered architecture review. The AI analyzes the current canvas and provides actionable feedback: single points of failure, missing components, scalability concerns, security gaps. This is spi AI's first major differentiator — Ghost AI generates, spi AI also reviews.

## Dependencies

- P3.1 (AI Engine) — need Trigger.dev for background critique job
- P2.1 (Canvas Node Types) — need canvas data to analyze

## Scope

### Build

- **"Review" button** — in workspace navbar, triggers AI analysis via Trigger.dev background job
- **Critique panel** — slides out from right side, shows categorized issues
- **Issue cards** — severity icon, title, description, affected node(s), actionable suggestion
- **Severity levels:**
  - **Critical** (red) — system will fail in production (no redundancy, no auth, exposed DB)
  - **Warning** (yellow) — works but risky (no caching, synchronous heavy tasks, no monitoring)
  - **Suggestion** (blue) — improvements (add CDN, consider event-driven, add logging)
- **Canvas highlights** — nodes with issues get colored ring matching severity
- **Click-to-focus** — clicking an issue pans canvas to the affected node
- **Dismiss** — user can dismiss individual issues (persisted in session)
- **Review categories:** Reliability, Scalability, Security, Completeness, Best Practices
- **Empty canvas guard** — "Nothing to review" message if canvas has no nodes

### Do NOT Build

- Auto-fix (that's P4.2 — refinement handles fixes)
- Historical review comparison
- Custom review rules
