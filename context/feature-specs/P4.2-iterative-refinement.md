# P4.2 — Iterative Refinement

## Goal

Follow-up prompts modify the existing canvas instead of regenerating from scratch. "Add a caching layer between API and database." "Split the monolith into three microservices." The AI returns diff operations (add, remove, update, move) that merge with the current canvas.

## Dependencies

- P3.2 (Prompt to Canvas) — need base generation working
- P3.1 (AI Engine) — need both streaming and background AI

## Scope

### Build

- **Refinement mode** — prompt bar automatically switches to "Refine" when canvas has nodes
- **Context injection** — current canvas state (serialized) included in the AI prompt
- **Diff operations** — AI returns structured operations:

| Operation | Effect |
|-----------|--------|
| `ADD_NODE` | New node placed on canvas |
| `REMOVE_NODE` | Node fades out and is deleted |
| `UPDATE_NODE` | Node label, description, or type changes |
| `MOVE_NODE` | Node repositions |
| `ADD_EDGE` | New connection drawn |
| `REMOVE_EDGE` | Connection removed |

- **Change highlighting** — newly added nodes pulse green (1.5s), modified nodes pulse blue (1.5s), removed nodes fade out (0.5s) via Framer Motion
- **Merge strategy** — AI output merges with existing canvas. Untouched nodes/edges stay exactly where they are.
- **Undo refinement** — Liveblocks history batches the entire refinement as one undo step
- **Conversation thread** — prompt bar shows count of refinements made ("Refinement 3")

### Do NOT Build

- Branching/forking (exploring multiple refinement paths)
- Visual diff comparison (before/after side-by-side)
- Refinement suggestions (that's P4.3)
