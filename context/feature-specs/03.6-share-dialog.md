# 03.6 — Share Dialog

Add a `Share` button to the workspace navbar that opens a share dialog for managing project collaborators.

## Owner Capabilities

- Invite collaborators by email
- View current collaborators with role badges ("Owner" / "Editor")
- Remove collaborators with confirmation ("Remove [name]? They'll lose access to this project.")
- Copy the project link with inline checkmark feedback (auto-resets after 2s)

## Collaborator Capabilities

- View the collaborator list (read-only)
- Cannot invite, remove, or manage access

## Invite Validation

Before sending an invite, validate inline:

- Invalid email format — show "Enter a valid email"
- Already a collaborator — show "Already added"
- Self-invite — show "That's you"

## Collaborator Display

Each collaborator row shows:

- Avatar (from Clerk) or fallback initial circle
- Display name (from Clerk) or email if no Clerk user found
- Role badge: "Owner" (indigo) or "Editor" (default)
- Remove button (owner-only, not shown on the owner's own row)

### Pending State

If an invited email has no Clerk account yet, show:

- Email only (no avatar, no display name)
- "Invited" badge in muted style
- Still removable by the owner

## Empty State

When no collaborators exist, show: "No collaborators yet — invite someone to start collaborating" with the invite input prominently placed below.

## Clerk User Enrichment

Collaborators are stored by email in the database. Use Clerk Backend API to enrich collaborator emails with:

- Display name
- Avatar image

If a Clerk user is not found for an email, fall back to showing the email only with an initial circle avatar.

## Copy Link

- Copy the current project URL to clipboard
- Show a checkmark icon replacing the copy icon for 2s, then reset
- No toast — inline feedback only

## Keyboard & Accessibility

- `Enter` submits the invite input
- `Escape` closes the dialog
- Focus trap inside the dialog
- All interactive elements have accessible labels

## API Routes

### GET /api/projects/[projectId]/collaborators

- Returns list of collaborator emails for the project
- Enriches each email with Clerk user data (name, avatar)
- Requires auth — caller must be owner or collaborator

### POST /api/projects/[projectId]/collaborators

- Body: `{ email: string }`
- Adds a collaborator to the project
- Validates: email format, not already added, not self-invite
- Requires auth — caller must be owner

### DELETE /api/projects/[projectId]/collaborators/[collaboratorId]

- Removes a collaborator from the project
- Requires auth — caller must be owner

## Access Control Updates

Update `lib/project-access.ts` to grant access to collaborators (not just the owner).

## Check When Done

- Share dialog opens from the workspace navbar
- Owners can invite and remove collaborators
- Collaborators see read-only collaborator list
- Role badges ("Owner" / "Editor" / "Invited") display correctly
- Collaborator names and avatars load from Clerk when available
- Pending invites show email-only with "Invited" badge
- Inline invite validation works (invalid email, duplicate, self)
- Copy link shows inline checkmark feedback
- Remove confirmation dialog appears before removing
- Empty state shows when no collaborators exist
- Keyboard support: Enter to invite, Escape to close
- `npm run build` passes
