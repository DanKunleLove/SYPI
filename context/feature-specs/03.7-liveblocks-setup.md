## Configuration — `liveblocks.config.ts`

### Presence

Tracks each user's realtime state in the room. Inspired by Figma/Miro presence systems.

```typescript
Presence: {
  cursor: { x: number; y: number } | null;  // null = cursor outside canvas
  selectedNodeIds: string[];                  // highlight what user is working on
  isThinking: boolean;                        // AI operation in progress
  viewportBounds: { x: number; y: number; width: number; height: number } | null;
}
```

- `selectedNodeIds` — other users see selection outlines (like Figma)
- `viewportBounds` — enables "follow user" viewport feature in future units

### UserMeta

```typescript
UserMeta: {
  id: string;
  info: {
    name: string;
    avatar: string;
    cursorColor: string;  // deterministic from user ID
  };
}
```

### Storage

Define initial canvas storage shape so Unit 06 doesn't need to refactor the config. Start with empty LiveMaps.

```typescript
Storage: {
  nodes: LiveMap<string, LiveObject<CanvasNode>>;
  edges: LiveMap<string, LiveObject<CanvasEdge>>;
}
```

The `CanvasNode` and `CanvasEdge` types are defined in `lib/types/canvas.ts` (created in Unit 06). For now, use placeholder types in the config with a `TODO` comment.

RoomEvent:
  | { type: "AI_GENERATION_START" }
  | { type: "AI_GENERATION_COMPLETE" }
  | { type: "NODE_HIGHLIGHT"; nodeId: string }

### Cursor Color Helper

Deterministically maps a user ID to a consistent color from a 12-color palette. Colors must be accessible on dark backgrounds (inspired by Figma's cursor palette).

```typescript
const CURSOR_COLORS = [
  "#ef4444", "#f97316", "#eab308", "#22c55e",
  "#14b8a6", "#06b6d4", "#3b82f6", "#6366f1",
  "#8b5cf6", "#a855f7", "#ec4899", "#f43f5e",
] as const;

export function getCursorColor(userId: string): string {
  let hash = 0;
  for (let i = 0; i < userId.length; i++) {
    hash = (hash << 5) - hash + userId.charCodeAt(i);
    hash |= 0;
  }
  return CURSOR_COLORS[Math.abs(hash) % CURSOR_COLORS.length];
}
```

## Auth Route — `POST /api/liveblocks-auth`

This route issues Liveblocks session tokens for authenticated users.

### Flow

1. Require Clerk authentication — return 401 if no session
2. Read `room` from the request body (this is the project ID)
3. Verify project access using `getProjectWithAccess()` — return 403 if forbidden
4. Ensure the Liveblocks room exists (create if needed), set room metadata:
   - `projectName`: project name
   - `ownerId`: project owner ID
5. Return a session token via `liveblocks.prepareSession()` with:
   - User ID
   - User info: name, avatar, generated cursor color

### Error Responses

| Status | Condition |
|--------|-----------|
| 401 | No Clerk session |
| 403 | User has no access to the project |
| 400 | Missing `room` in request body |

## LiveblocksRoom Wrapper — `components/editor/liveblocks-room.tsx`

A client component that wraps children with `LiveblocksProvider` and `RoomProvider`.

### Props

- `roomId: string` — the project ID used as room ID
- `children: ReactNode`

### Behavior

- Configures `LiveblocksProvider` with `authEndpoint="/api/liveblocks-auth"`
- Sets `RoomProvider` with the `roomId` and initial presence:
  - `cursor: null`
  - `selectedNodeIds: []`
  - `isThinking: false`
  - `viewportBounds: null`
- Shows a loading skeleton while connecting
- Shows an error state if connection fails
